# V2 Tooling Decision Matrix — Travelliniwithus (2026-06-28)

Ricerca tecnica da Principal Architect su tutto l'ecosistema React/WebGL per costruire la V2 (home scroll-storytelling "L'Atlante", mappa come prodotto centrale, paesaggi 3D, editoriale, SEO, shop futuro). Prodotta da un workflow a 13 agenti con verifica live su web + context7. Ancorata al verdetto autorevole dell'[[AUDIT_V1_VS_V2_2026-06-27]] (restare su Vite, potenziare, niente Next.js/Sanity finche' non c'e' attrito misurato) e a cosa e' gia' installato in `package.json`.

> Nota metodo: 8/8 ricerche di categoria riuscite + 3/5 verifiche adversariali verificate sul web (Mappa, CMS, GSAP/3D). Le 2 verifiche fallite (Next.js-vs-Vite, compat UI-libs) per un cap tecnico sull'output strutturato sono state ricostruite a mano dai rispettivi cluster di ricerca (completi) + audit; sono marcate [sintesi].

---

## VERDETTO (TL;DR)

**La cassetta attrezzi della V2 e' gia' ~70% installata e corretta.** La V2 NON e' un cambio di stack: e' potenziare React 19 + Vite 6 + Tailwind 4 + R3F + Firestore + Stripe con **pochi innesti mirati**. Le uniche due mosse strutturali sono: (1) **rendere la home cinematica davvero indicizzabile** con SSG/prerender build-time (senza Next.js), (2) **migrare il motore mappa da Mapbox a MapLibre** (la mappa e' il prodotto, e Mapbox e' proprietario + token-gated + stili non self-hostabili). Tutto il resto e' "keep" o aggiunta leggera.

---

## Le 5 decisioni ad alto rischio — risolte

### 1. Next.js vs Vite + SSG -> RESTA SU VITE, aggiungi SSG [sintesi]

- **Scartare** la migrazione a Next.js App Router (D). Nessun beneficio misurato; costringerebbe a rifare manualChunks/modulePreload/dedupe gia' tunati, PWA, API Express, l'admin CMS Firestore, e probabilmente un cambio host. Rischio concreto di abbandono a meta' (gia' successo col "definitivo").
- **Gap reale** (home indicizzabile solo via sr-only/fallback) -> chiuderlo con **SSG/prerender build-time** restando su `react-router-dom` 7. Due leve valide, leggera tensione tra cluster: il cluster framework propone `vite-react-ssg` (B, valutare in lab); il cluster perf propone il **prerender NATIVO di React Router 7** (`ssr:false` + lista prerender, nessuna nuova dipendenza). **Reco: bake-off breve in lab, preferendo il prerender nativo RR7** (in-famiglia, zero dep); fallback a vite-react-ssg se non si sposa con l'attuale BrowserRouter. R3F/Mapbox dietro `ClientOnly` (montano solo client-side). **Scegliere UN solo layer di rendering + un modello di router prima di costruire molte pagine V2.**
- **Host**: tenere Firebase Hosting; Vercel = solo prototipo (ISR/edge irrilevanti per build statico SSG).

### 2. Mappa: MapLibre vs Mapbox -> MIGRA A MAPLIBRE [verificato, alta confidenza]

- Tenere `react-map-gl` come wrapper, **cambiare il motore** da Mapbox GL JS v3 (proprietario dal v2, token client obbligatorio, stili non self-hostabili) a **MapLibre GL JS** (BSD-3). Driver = lock-in + ownership dello stile (non il conto: Mapbox ha 50k load/mese free, nessuna bolletta imminente).
- Azione (smallest-change): in `src/components/map/MapboxWorldMap.tsx` cambiare l'import `react-map-gl/mapbox` -> `react-map-gl/maplibre` (Map/Marker/Popup/NavigationControl/flyTo portano 1:1), togliere la prop token, swap CSS `mapbox-gl` -> `maplibre-gl`, `mapStyle` -> stile **OpenFreeMap** ristilizzato sand/ink (PMTiles self-hosted in Fase 2). **RIABILITARE `attributionControl`** (obbligo legale con dati OSM/ODbL). Re-gate del fallback editoriale su errore di caricamento stile invece che su token mancante. Zero rischio parita' per cio' che spedisce oggi (usa solo `pitch:45`); MapLibre v5 copre il futuro momento "mappa dall'alto"/globo + terreno 3D.
- Geocoding **offline a import-time** (Photon/Nominatim): le coord si salvano una volta, non per-utente -> nessun geocoder runtime a pagamento. `supercluster` solo quando il dataset pin supera il seed. **Niente deck.gl** sulla mappa funzionale (cool-not-clearer).

### 3. Serve un CMS? -> NO, tieni Firestore + admin [verificato, alta confidenza]

- V2 **non** ha bisogno di Sanity/Payload/Strapi/Directus ora. Firestore + admin custom (SiteContentEditor/ArticleEditor/ProductEditor, ~2095 righe, schema-driven via `siteContent.ts`) restano l'unica fonte. **Estendere** con nuove collection Firestore + form admin per pin/posti/itinerari della mappa (oggi vivono in TS statico) — lavoro reale ma e' la mossa giusta: sono dati relazionali/queryable che alimentano mappa, ricerca (fuse.js), cluster e schema.org.
- **Scartare** Payload (Next-native -> migrazione rifiutata), Strapi/Directus (DB duplicato accanto a Firebase; Directus e' BSL, non OSI).
- **Trigger futuro** (solo se l'editing costa tempo reale): layer git-based **Keystatic** (MIT, preferito) o TinaCMS per il **long-form markdown in-repo soltanto** — mai per pin/posti/prodotti relazionali; **Sanity** solo come ultima risorsa hosted multi-editor. Caveat: Keystatic in GitHub-mode richiede runtime Node per OAuth e mira a Next/Astro/Remix -> su questo stack Vite+Express+Firebase e' wiring reale, non drop-in. Local-mode e' il punto di partenza a zero attrito.

### 4. GSAP licenza + pipeline 3D + Theatre.js -> NESSUNA nuova dipendenza ora [verificato, alta confidenza]

- **GSAP e' 100% gratis** (post acquisizione Webflow, ~apr/mag 2025), inclusi TUTTI gli ex-plugin Club (ScrollTrigger, SplitText, MorphSVG, ScrollSmoother, Flip...) e per uso commerciale. Nessun tier a pagamento, nessun catch. -> Nessun blocco licenza per l'Atlante.
- **Pipeline asset 3D NON giustificata adesso**: zero file .glb/.gltf nel codebase, scene = geometria procedurale + GLSL ShaderMaterial. Comprimere il nulla non da' nulla. **Trigger**: al primo modello texturizzato reale, adottare UN solo tool offline = `gltfjsx --transform` (wrappa glTF Transform: Draco + KTX2 + prune/dedup). Default Draco (drei `useGLTF` lo auto-decodifica); meshopt solo se il modello ha animazioni/morph; KTX2 solo per texture 3D (mai per immagini 2D, che restano su OptimizedImage AVIF/WebP).
- **Theatre.js = overkill/lab-only** (repo pubblico fermo da apr 2024, React 18 interno, alto lock-in). Per la camera: autorare in `/atlante-lab` e **rigiocare le keyframe via GSAP** in prod, non spedire il runtime di Theatre.

### 5. Librerie UI / design system -> layer sottile OWNED, niente lib wholesale [sintesi]

- Costruire il design system come **layer sottile di proprieta'** su Tailwind 4 + CSS vars. **Non** adottare nessuna component-library in blocco.
- Fondamenta: tenere **lucide-react** (A, unica icon-set). Aggiungere la convenzione `cn()` via **tailwind-merge + cva** (oggi il repo NON ha helper cn, compone classi con template literal raw -> si rompe con le varianti).
- Layer comportamento: scegliere UN set di primitive headless — bake-off **Radix vs Base UI 1.0**; propendere per **Base UI** per i filtri mappa (ha Combobox/Autocomplete che a Radix manca). Entrambi React 19 + TW4 ok.
- **shadcn/ui** solo come CLI copy-paste-to-own (ora pieno supporto TW4 + React 19), ristilizzato sand/ink prima del merge — mai il tema SaaS di default.
- **Solo reference/prototipo (E)**: Aceternity, Magic UI, React Bits, Eldora, Animate UI, Motion Primitives (TW4 solo "partial", e possiedi gia' motion+GSAP+R3F+drei+postprocessing). Al massimo un effetto isolato ricostruito in-palette in `/atlante-lab`. **Scartare Hover.dev** (a pagamento, redistribuzione ristretta, SaaS, ridondante).

## Decision Matrix completa (per categoria)

### Core framework, rendering & hosting

> **Raccomandazione cluster:** Stay React 19 + Vite 6 + Tailwind 4 + react-router-dom 7 on Firebase Hosting — all keep, no migration. Honor the 2026-06-27 audit: explicitly DISCARD a Next.js App Router migration (no measured benefit; it would force redoing the tuned manualChunks/modulePreload/dedupe, PWA, Express API, and Firestore admin CMS, and likely a host move) and keep Vercel as prototype-only since its ISR/edge value is irrelevant to a static-SSG build. The one real rendering gap — the cinematic home + editorial/place pages being only weakly indexable (sr-only + fallback today) — is best closed by adding build-time SSG with vite-react-ssg (B, evaluate first in a lab branch): it prerenders the existing react-router-dom routes to static HTML that Firebase Hosting already serves, with R3F/Mapbox kept behind ClientOnly so they mount only client-side, and the prerender slug list wired to the existing sitemap source. Treat React Router 7 framework mode as C-optional (adopt only if V2 later needs route loaders + request-time SSR) and vike as E-prototype-only (consider only if all-or-nothing hydration proves too heavy and true per-page islands become necessary). Avoid stacking SSG approaches: pick exactly one rendering layer and one router model before building many V2 pages. Keep react-helmet-async 3.0 for per-route meta/JSON-LD and use its SSR context when wiring SSG; define the sand/ink design tokens once as Tailwind 4 @theme CSS variables rather than a parallel JS token file.
