# V2 Tooling Decision Matrix — Travelliniwithus

**Ruolo**: Principal Architect (React, Next.js, WebGL & Travel Editorial Ecosystem)  
**Data**: 2026-06-29  
**Stato**: Approvato ed Operativo

Questo documento definisce la cassetta degli attrezzi tecnica ottimale per costruire la V2 di **TRAVELLINIWITHUS** (home scroll-storytelling "L'Atlante", mappa interattiva come prodotto centrale, storytelling cinematico, performance d'eccellenza, SEO nativa ed accessibilità).

> [!IMPORTANT]
> **Principio Guida V2:** Evitare l'effetto "Frankenstein" di librerie. Il 3D deve essere un potenziamento estetico (canvas = enhancement), mentre il contenuto deve risiedere nel DOM (HTML = contenuto reale per SEO e accessibilità). La mappa deve garantire controllo e costi prevedibili. La tecnologia deve servire l'estetica premium editoriale senza cadere nel look SaaS generico.

---

## 1. Architettura di Fondo e Verdetto Strategico (TL;DR)

La cassetta degli attrezzi di TRAVELLINIWITHUS è già per il **~70% corretta e installata** nel codebase. La V2 non richiede una migrazione distruttiva di framework, ma un potenziamento chirurgico.

### Le Tre Decisioni Chiave:

1. **No Next.js (Restare su Vite 6 + React 19 + Express):** La migrazione a Next.js App Router comporterebbe un costo di refactoring enorme (PWA, server custom Express, admin Firestore, chunk-splitting e deduplicazione di Three.js) senza vantaggi misurabili. L'unico vero gap di Vite (SEO sulla home 3D e sulle pagine dinamiche) si risolve introducendo il **prerendering statico (SSG)** build-time integrato nativamente in **React Router 7** o tramite **vite-react-ssg**.
2. **Migrazione Mappa (da Mapbox GL a MapLibre GL):** La mappa è il prodotto centrale. Usare Mapbox GL v3 (proprietario, token client obbligatorio e bollette potenzialmente illimitate) è un rischio di lock-in. Migrando a **MapLibre GL JS** (open source BSD) mantenendo `react-map-gl` come wrapper, si eliminano i token obbligatori e i costi per-map-load, adottando stili vettoriali aperti (come **OpenFreeMap** restilizzato o PMTiles self-hosted).
3. **No CMS Esterni (Firestore + Custom Admin):** Firestore e l'editor admin custom (~2095 righe, schema-driven tramite `siteContent.ts`) rimangono l'unica fonte di verità. Adottare Sanity o Payload adesso creerebbe un secondo backend duplicato. La scelta corretta é estendere Firestore con collection per i pin della mappa, i posti e gli itinerari (oggi statici in TS).

## 4. Linee Guida per l'Implementazione della V2

1.  **Rendering Ibrido (ClientOnly):** Quando si introduce l'SSG, tutti i componenti 3D (R3F Canvas) e le mappe (`react-map-gl`) devono essere montati dietro un wrapper `<ClientOnly>` per evitare errori di build dovuti alla mancanza dell'oggetto `window` sul server di prerendering.
2.  **Unicità del Router:** Scegliere un solo modello di rendering statico e configurarlo prima di avviare lo sviluppo di nuove pagine V2 per evitare doppie integrazioni.
3.  **Attribuzione Obbligatoria sulla Mappa:** Passando a MapLibre + OpenFreeMap, reimpostare `attributionControl={true}` per rispettare i requisiti legali dei dati OpenStreetMap/ODbL.
4.  **Sicurezza Monetizzazione:** Mantenere Stripe Checkout lato server (Express) per proteggere i prezzi dei prodotti digitali da manomissioni client-side.
5.  **A11y & prefers-reduced-motion:** Ogni timeline di scroll-storytelling creata con GSAP/ScrollTrigger deve verificare la preferenza utente di animazione ridotta e, in caso positivo, montare la versione statica HTML (`Fallback`).
